# Deferred feature instructions

F01–F12 are a prepared expansion queue, not part of the initial continuous-build scope. Start an F task when the user selects it or approves an expanded milestone with its entry condition satisfied. Use the same implement/verify/checkpoint loop and stable contracts. No future feature is currently started.

| ID | Entry condition | Instructions when selected | Acceptance and boundary |
| --- | --- | --- | --- |
| F01 More units/subjects | First cycle useful and review capacity available | Select one new unit, review its references, author original items, add a versioned pack and resource mappings. Exercise both new and old history. | Existing rules remain stable; new content is reviewed; do not bulk-harvest all Grade 9. |
| F02 Multiple students/accounts | Real separate users need access | Specify identities and permissions, migrate ownership, implement authentication and server-side authorization for every record/file, add isolation tests. | Cross-user reads/writes/exports are denied; role toggles alone never satisfy isolation. |
| F03 Hosted or home-network access | Home-network synthetic mode authorized 2026-10-05 and implemented as U01/D15; authenticated hosting remains future work | Review deployment/data location, TLS, authentication, secrets, persistent storage, backup and recovery. Choose one hosting target and demonstrate staged recovery before release. | Explicit deployment authorization and applicable access controls; no incidental public exposure or ephemeral DB. |
| F04 LMS/calendar integrations | Manual burden measured and access available | Select one integration, verify official API/permissions, add least-privilege read access, mapping/review and idempotent sync with disconnect behavior. | Unauthorized attachments remain unavailable; deletion/disconnection behavior works; no school password scraping. |
| F05 Conversational tutor | Structured evidence workflow reliable | Define conversation scope, bounded context selection, grounding, off-topic behavior, history retention and evaluated prompts. Make chat reference existing records. | Conversation cannot silently create facts or assessed mastery; core sessions remain usable without chat. |
| F06 Automatic item generation | Validation/review capacity established | Generate drafts into a queue, verify numerical keys/units and rubrics, assess duplicate/exposure risks, record source/rights and reviewer decisions. | Only eligible reviewed versions enter real practice/reassessment; generator never self-certifies expertise. |
| F07 More formats/advanced extraction | Pilot failures justify format support | Add one format/diagram class, explicit limits, fixture corpus, review UI and accuracy/abstention evaluation. Keep original artifacts and manual correction. | Supported errors and false readings measured; no blanket handwriting/circuit understanding claim. |
| F08 Live discovery/embedding/transcripts | Curated catalogue inadequate and rights resolved | Choose one capability; verify provider terms, perform bounded discovery, keep results candidate until reviewed, implement failure/privacy behavior. | No student data in search/URLs; hosting/transcript permission separate from linking; no endless media feed. |
| F09 Better search | Structured filtering demonstrably insufficient | Establish retrieval test queries and expected sources, try full-text search first, compare embeddings only if necessary and permitted. | Measured improvement justifies storage/index complexity; provenance/deletion reach the index. |
| F10 Jobs/servers/PostgreSQL | Measured latency/contention or deployment requires it | Select the smallest change, preserve operation idempotency and stable IDs, write migration/reconciliation/rollback tests. | No lost/duplicated evidence and verified backup/restore; more infrastructure must solve a recorded problem. |
| F11 Offline sync/native package | Required usage pattern established | Choose packaging or sync explicitly. Packaging preserves data paths/upgrades; sync defines identity, conflict resolution, encryption/access and deletion propagation. | Device loss/conflicts/retries have tested outcomes; don't sync a live SQLite file through a file-sharing folder. |
| F12 Advanced analytics or product features | Evidence of value and a separate user decision | Split the chosen feature into its own evaluated task: calibrated learning model, non-punitive motivation, billing, or parent reporting. Define purpose and measurable effect before implementation. | No speculative bundle; no causal/psychometric claims without evidence; monetization gets a fresh content-rights review. |

When adding an F task to the active queue, give it B-like detailed cards and acceptance cases for the actual chosen scope, record dependencies in BUILD_STATE, and update the architectural decision only where the new requirement demands it.
